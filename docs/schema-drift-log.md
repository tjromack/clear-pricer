# Schema-drift log

The record of every time an upstream source (a CMS hospital price file, an NPPES dump) deviated from the expected
schema — **what changed, when it was observed, and how the pipeline handled it** (mapped, quarantined, or logged as
unmappable — never silently dropped). This log is the spine of the case study and is written *as drift is encountered*,
not reconstructed afterwards.

Entry template:

| Date observed | Source | What drifted | How the pipeline handled it | Follow-up |
|---|---|---|---|---|
| 2026-09-28 | UChicago MRF (`363488183_…_standardcharges.json`, v3.0.0) | File begins with a **UTF-8 byte-order mark**. RFC 8259 forbids a BOM in JSON; Python `json.load(encoding='utf-8')` rejects the file outright (`Unexpected UTF-8 BOM`). | M0 profiling: decoded as `utf-8-sig`, after which the whole file parses. No pipeline code yet. | M1/M2 parser: strip a leading BOM on every source, and record `had_bom` in the drift/unmappable log so the anomaly stays visible. |
| 2026-09-28 | Rush `cms-hpt.txt` | `mrf-url` and `source-page-url` have **no URL scheme** (`apps.para-hcfs.com/PTT/FinalLinks/Reports.aspx?…`, `www.rush.edu/…`). The CMS `cms-hpt.txt` spec expects a full URL. | M0: prefixed `https://` by hand; the URL resolves (HTTP 200). | Discovery code normalises scheme-less URLs to `https://` and logs each one it fixed. |
| 2026-09-28 | Rush MRF location | The file is not at an EIN-named URL. A vendor ASPX endpoint (`para-hcfs.com`, `dbName=dbRUMCCHICAGOIL&type=CDMWithoutLabel&fileType=CSV`) serves it, and the EIN filename (`362174823_rush-university-medical-center_standardcharges.csv`) appears only in `Content-Disposition`. The response has **no `Content-Length` and no `Last-Modified`**. | M0: saved under the `Content-Disposition` filename and hashed it (SHA-256). | Change detection for Rush can't use HTTP headers. The DAG must hash the body to decide "new file vs. same file" (idempotency pin). |
| 2026-09-28 | All three MRFs (code types) | **CPT codes are typed inconsistently, across hospitals and within one file.** UChicago and Rush have no `CPT` type at all; CPT codes go under `HCPCS`. Rush has 114,000 five-digit numeric and 514 Category III (`nnnnT`) codes typed `HCPCS`, and UChicago types `0232T` as `HCPCS`. NM mostly uses `CPT` (14,255 numeric + 50 Cat III), but it also has 108 numeric codes typed `HCPCS` and 1,037 HCPCS-Level-II-shaped codes (`A1234`) typed `CPT`. | M0: counted only. | Staging keeps the source `code_type` verbatim and adds a derived `code_family` (CPT / CPT Cat III / HCPCS Level II, by pattern). Any row where the declared and derived types disagree goes to the drift log. The M7 same-CPT comparison joins on `code_family`, not the declared type. |
| 2026-09-28 | Rush (CSV) + NM (JSON) | **Allowed-amount stats contradict themselves.** Some rows have `count = "0"` with a non-empty `median_amount`, 10th and 90th percentile (a median of zero claims): 72,831 of 208,409 rows at Rush, and 6,523,094 of 7,026,150 payer rows (93%) at NM, where every payer row carries a median. UChicago has 0 such rows. | M0: counted; not yet handled. | M1/M2: a dbt test measures `count = 0 AND median_amount IS NOT NULL` per hospital. Decide (→ DECISIONS) whether those medians are nulled, quarantined or annotated. They must never feed a price comparison as observed amounts. |
| 2026-09-28 | Rush (CSV) + NM (JSON) | **Two rates on one row.** A dollar rate and a percentage rate appear together: 74,067 Rush rows (`negotiated_dollar` + `negotiated_percentage`) and 6,624,501 NM payer rows (`standard_charge_dollar` + `standard_charge_percentage`, where 6,804,307 of NM's rows are `percent of total billed charges`). With both present, which one is the price is ambiguous. UChicago has 0 such rows. | M0: counted only. | Record a precedence rule as a decision before staging (candidate: keep both, and flag `rate_basis` = percentage when methodology is percent-of-billed). |
