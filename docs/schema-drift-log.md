# Schema-drift log

The record of every time an upstream source (a CMS hospital price file, an NPPES dump) deviated from the expected
schema — **what changed, when it was observed, and how the pipeline handled it** (mapped, quarantined, or logged as
unmappable — never silently dropped). This log is the spine of the case study and is written *as drift is encountered*,
not reconstructed afterwards.

Entry template:

| Date observed | Source | What drifted | How the pipeline handled it | Follow-up |
|---|---|---|---|---|
| 2026-09-28 | UChicago MRF (`363488183_…_standardcharges.json`, v3.0.0) | File begins with a **UTF-8 byte-order mark**. RFC 8259 forbids a BOM in JSON; Python `json.load(encoding='utf-8')` rejects the file outright (`Unexpected UTF-8 BOM`). | M0 profiling: decoded as `utf-8-sig`, after which the whole file parses. No pipeline code yet. | M1: staging detects and strips a leading BOM on every source and logs `utf8_bom_stripped` (CSV path done; the JSON path for UChicago lands in M2). |
| 2026-09-28 | Rush `cms-hpt.txt` | `mrf-url` and `source-page-url` have **no URL scheme** (`apps.para-hcfs.com/PTT/FinalLinks/Reports.aspx?…`, `www.rush.edu/…`). The CMS `cms-hpt.txt` spec expects a full URL. | M0: prefixed `https://` by hand; the URL resolves (HTTP 200). | **Done in M1:** `discovery.normalise_url` adds `https://`, and every fix is logged as `discovery_*_missing_scheme` in `rpt_source_conformance` on each fetch. |
| 2026-09-28 | Rush MRF location | The file is not at an EIN-named URL. A vendor ASPX endpoint (`para-hcfs.com`, `dbName=dbRUMCCHICAGOIL&type=CDMWithoutLabel&fileType=CSV`) serves it, and the EIN filename (`362174823_rush-university-medical-center_standardcharges.csv`) appears only in `Content-Disposition`. The response has **no `Content-Length` and no `Last-Modified`**. | M0: saved under the `Content-Disposition` filename and hashed it (SHA-256). | **Done in M1:** landing is content-addressed (`raw/hpt/rush/<sha256[:16]>/`), so an unchanged file is a no-op and a changed file lands beside the old one. |
| 2026-09-28 | All three MRFs (code types) | **CPT codes are typed inconsistently, across hospitals and within one file.** UChicago and Rush never use `CPT`; CPT codes go under `HCPCS` (Rush: 114,000 Category I + 514 Category III; UChicago types `0232T` as `HCPCS`). NM mostly uses `CPT`, but it also types 108 numeric codes as `HCPCS` and 1,037 HCPCS-Level-II-shaped codes (`A1234`) as `CPT`. *Corrected 2026-09-29:* CPT is HCPCS Level I, so a CPT code typed `HCPCS` is **valid, just ambiguous**. Only the NM `A1234`-as-`CPT` pattern is a real type conflict. | **M1 (CP-DEC 006):** the declared type is kept verbatim; `code_family` is derived from the code's shape (CPT Cat I/II/III/PLA, HCPCS II, CDT); `type_conflict` flags only true contradictions. Rush in M1: 114,000 `CPT_CAT_I` + 514 `CPT_CAT_III` + 58,698 `HCPCS_II`, all declared `HCPCS`, 0 conflicts. | **Measured in M2:** NM has exactly 1,037 `cpt_declared_not_cpt` conflicts, matching the M0 profile. The M7 comparison joins on `code_family`. |
| 2026-09-28 | Rush (CSV) + NM (JSON) | **Allowed-amount stats contradict themselves.** Some rows have `count = "0"` with a non-empty `median_amount`, 10th and 90th percentile (a median of zero claims): 72,831 of 208,409 rows at Rush, and 6,523,094 of 7,026,150 payer rows (93%) at NM, where every payer row carries a median. UChicago has 0 such rows. | **M1 (CP-DEC 006):** the clean columns are **nulled** (not zeroed), with `allowed_amounts_suppressed = 'count_zero'`; the raw values stay in `*_raw`. A dbt gate fails the run if one ever leaks into the clean columns. Rush in M1: 72,831 rows (34.9% of records) suppressed. The spec agrees: *"If the count of allowed amounts is zero, do not encode these data elements."* | **Measured in M2:** NM has 6,523,094 rows (92.8% of payer rows) suppressed; UChicago 0. |
| 2026-09-28 | Rush (CSV) + NM (JSON) | **Two rates on one row.** A dollar rate and a percentage rate appear together: 74,067 Rush rows (`negotiated_dollar` + `negotiated_percentage`) and 6,624,501 NM payer rows (`standard_charge_dollar` + `standard_charge_percentage`, where 6,804,307 of NM's rows are `percent of total billed charges`). With both present, which one is the price is ambiguous. UChicago has 0 such rows. | **M1 (CP-DEC 006):** the dollar is the price; `rate_basis` records its origin. Rush in M1: of 74,067 dual rows, **68,877 are pct × gross within one cent** (`dollar_from_percent`; the dollar is just a percentage of the chargemaster price) and **5,190 don't reconcile** (`dollar_percent_unreconciled`, e.g. $203.04 at 30% of a $432 gross). All 208,409 Rush rows carry a dollar. | M7 decides whether `dollar_from_percent` rows count as negotiated prices; the default is to exclude them. |
| 2026-09-29 | Rush MRF (dollar precision) | **Percentage-derived dollars are truncated, not rounded,** on some rows: 61% × $2.14 = $1.3054 is published as `1.30` (rounding would give `1.31`). | M1: reconciliation tolerates < 1 cent against the exact product, so both conventions reconcile. The first attempt compared rounded floats and mis-flagged 1,037 truncated rows as unreconciled; the float difference 1.31 − 1.30 is slightly more than 0.01. | Regression tests pin the truncated, rounded and 2-cent-off cases (`tests/test_rules.py`). |
| 2026-09-29 | UChicago MRF (code types) | 14 codes typed `HCPCS` matched no pattern in the first classifier. 13 are **CPT MAAA codes** (`0002M`–`0019M`, multianalyte assays with algorithmic analyses: 4 digits + `M`), a CPT category the classifier had left out. One, `7746A`, fits no CPT or HCPCS shape. | M2: added `CPT_MAAA` (`\d{4}M`) to the standard's pattern set (UChicago 13, NM 1). `7746A` stays `UNCLASSIFIED` with `hcpcs_declared_unclassified`, so it's published, not guessed. | None; `7746A` is a real publisher anomaly. |
